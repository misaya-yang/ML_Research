# 首次通过的联合容量认证

问题是固定策略能否同时在步数和新增验证输入字节预算内首次通过。使用十个固定的、由存档候选及其标签构建的可行图；任务等权，轨迹从空验证缓存起步。不是线上服务，也不是对每个任务单独担保。

- **原 9× 结论不成立。** 人工推导确认一条标为正确的答案实际错误；删除该标签后，20 万个新回放的真实联合通过率是 **93.1125%**，95% 同时区间上界 **93.2474%**。原 95% 签发不能继续引用。
- **14× 重新确认了有实际区别的容量决策。** 先用独立的 20 万回放，仅看真实联合结果，从预定网格选出 14×，随后用 50 万个新回放只确认一次。保护一个已核对正确的标签，其余 540 个正身份允许至多再错一个。最坏真实联合通过率 **95.3382%**，同时区间 **[95.1776%, 95.4944%]**；用同任务独立回放正确估计两项边际后取乘积，最坏通过率 **94.1380%**，同时区间 **[93.9601%, 94.3116%]**。两者在同一预算下作出相反的 95% 决策；没有证明 14× 最小。
- **计入反事实续跑仍节省模型转移查询。** 14× 下，匹配的顺序前向和精确跳步各跑 50 万次，均认证最坏通过率超过 95%：前者 **95.3960% [95.2362%, 95.5515%]**，后者 **95.3376% [95.1770%, 95.4938%]**。含基准路径与实际续跑，残余转移查询由 **56,771,070** 降为 **33,774,514（少 40.51%）**；验证次数和新增输入字节基本不变。

这些结果只认证有限存档图和指定的一条额外假阳性，不涵盖多标签错误，也未完整语义复核其他标签。查询节省不是线上延迟、账单节省或独立外部任务复验。[核心理论与接口边界](../../theory/proofs/first_passage_core.md)。

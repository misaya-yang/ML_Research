# Joint Budget Certification for First Passage

We ask whether a fixed policy can obtain its first verified result within both a step budget and a budget on newly submitted verifier-input bytes. We use ten fixed, feasible graphs constructed from archived candidates and labels, weight tasks equally, and start each trajectory with an empty verification cache. These are not live service measurements or separate guarantees for each task.

- **The original 9× result does not hold.** An independent derivation showed that one answer labeled correct was wrong. Removing that label gives a true joint pass rate of **93.1125%** over 200,000 new replays, with a simultaneous 95% upper endpoint of **93.2474%**. The original 95% certification must not be cited.
- **At 14×, the joint calculation changes the capacity decision.** We selected 14× on a prespecified grid using only the true joint outcomes from 200,000 independent replays, then confirmed it once with 500,000 fresh replays. We protected one independently verified correct label and allowed up to one additional false positive among the remaining 540 positive identities. The worst-case true joint pass rate was **95.3382%**, with a simultaneous interval of **[95.1776%, 95.4944%]**. Multiplying the two correctly estimated marginals from independent replays within each task gave a worst-case pass rate of **94.1380%**, with simultaneous interval **[93.9601%, 94.3116%]**. The two calculations lead to opposite 95% certification decisions under the same budget. We do not establish that 14× is minimal.
- **Model-transition queries still fall after charging for counterfactual continuation.** At 14×, the matched chronological forward and exact-jump methods each ran 500,000 replays and certified a worst-case pass rate above 95%: **95.3960% [95.2362%, 95.5515%]** and **95.3376% [95.1770%, 95.4938%]**, respectively. Counting both the baseline paths and actual continuations, residual transition queries fell from **56,771,070** to **33,774,514 (40.51% fewer)**. Verification counts and newly submitted input bytes were essentially unchanged.

These results apply only to the finite archived graphs and the specified allowance for one additional false positive. They do not cover multiple label errors, and we have not independently checked all remaining labels for semantic correctness. Fewer queries do not establish lower production latency, lower bills, or replication on independent external tasks. See the [core theory and interface requirements](../../theory/proofs/first_passage_core.md).

The [forward-only search results](forward_search.md) give the one-sided stopping theorem, measured target-model work, and comparisons against practical alternatives on program generation and graph coloring.

For the separate real MBPP56 K4 workload, see the [reader-independent certificate replay](mbpp56_audit/README.md). Do not combine that timing comparison with the finite-graph certification here.
